The Golden Rule

Never click in the AWS console for things Terraform manages.
If you manually change something in AWS, Terraform doesn't know — that's called drift.
Next time you run terraform apply, it will revert your change.

3 Block Types

Creates things in AWS

data
Reads existing things (doesn't create)
Existing AMIs, ACM certs, VPCs...
output
Prints values after apply

Variables Pattern
variables.tf — declare it
variable "db_password" {
  type = string
  sensitive = true # hides from terminal
}
terraform.tfvars — provide value (never commit)
db_password = "ShopEasy2026!!"
main.tf — use it
password = var.db_password
⚡
resource vs data — Quick Reference
resource data
Does Creates & manages AWS resource Reads existing AWS resource
Example resource "aws_vpc" "main" data "aws_ami" "ubuntu"
Reference aws_vpc.main.id data.aws_ami.ubuntu.id
On destroy Deletes the resource Does nothing
Use when You own it / creating new Already exists (ACM cert, AMI)
💥 Hard-Won Lessons
🔥
Hard-Won Lessons (from real bugs)
💥
Password mangled? Never use $ @ / " in passwords. Bash interprets $2 as a variable and strips it. Use letters + numbers + ! only.
🔍
data block empty result? The domain/ARN must match exactly what's in AWS. We used *.zovie.app but cert was zovie.app.
🔐
GitHub Actions can't read secrets? Job has environment: DEV — it reads ONLY from DEV environment secrets, NOT repository secrets.
👆
Duplicate resources? You manually created something in AWS console before Terraform knew about it. Delete the manual resource first, then terraform apply.
⏳
RDS deletion hanging? Check skip_final_snapshot = true for dev. In prod set it to false — that's your last backup before deletion.
🔄
terraform apply modifying things you didn't change? Someone manually changed AWS console. That's drift — Terraform corrects it back to what the code says.
